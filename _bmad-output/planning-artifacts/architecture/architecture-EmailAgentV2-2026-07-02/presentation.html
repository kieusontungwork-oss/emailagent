Technical Architecture & Solution Design

Design Paradigm

Event-Driven, Modular Orchestration

The system is built around n8n acting as a stateless "Front Desk" coordinator.

  • Event-Driven: Pipeline awakens strictly on incoming Gmail triggers.
  • Modular: The main workflow does NO heavy lifting. It delegates extraction, querying, and formatting to isolated sub-workflows.
  • Stateless: The orchestrator holds no memory. All state, auditing, and idempotency relies on an external single-source-of-truth.

The 3 Architectural Invariants

These are the non-negotiable rules for anyone building or extending this system.

1. The Pure Orchestrator (State Model)

  • Rule: PostgreSQL is the absolute source of truth for both domain data AND operational state (request_logs).
  • Why: Prevents state fragmentation. Redis is banned from holding persistent idempotency logs.

2. The "Mailroom" Error Boundary

  • Rule: No sub-workflow is allowed to email the user or admin directly. ALL errors are routed back to the Controller and handed to a universal "Mailroom" sub-workflow.
  • Why: Prevents spaghetti logic and ensures consistent error formatting.

3. Git-Backed Deployments

  • Rule: n8n workflow JSON files must be treated as Infrastructure-as-Code and deployed to production via CI/CD.
  • Why: Prevents unaudited "UI click" changes in the secure, air-gapped production environment.

Approved Tech Stack

  • Orchestration: n8n (Queue Mode)
  • State & Queuing: Redis 7.x (Queues ONLY)
  • Database & Audit: PostgreSQL 16.x
  • AI Inference: LM Studio (Air-gapped local subnet)
  • Vision Model: Llama-3.2-Vision (or Qwen2-VL)
  • Secrets: HashiCorp Vault (Runtime injection)
  • Excel Generation: Python 3.12+ (openpyxl)
